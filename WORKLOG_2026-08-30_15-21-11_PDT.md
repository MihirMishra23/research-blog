## Design decisions

### Keep the README sufficient on its own

The README links to deeper design documents, but it does not require them for normal ownership tasks. It includes complete article and topic templates, permitted values, validation commands, reciprocal graph rules, publishing commands, and deployment recovery steps.

### Make authorship a top-level operating rule

The editorial boundary appears near the start of the README, inside the article template, and again at the publication gate. Documentation tests assert that the explicit statement remains present.

### Separate article publication from topic maturity

Articles use `status: draft|published|archived`, while topics use `draft` for visibility and `status` for conceptual maturity. The README calls out this distinction and explains every maturity value.

### Preserve hand-authored map intent

New topic instructions treat Markdown metadata as the source of truth and the V1 canvas as a composed editorial layout. The guide requires reciprocal relationships, explains when authored waypoints are appropriate, and warns against duplicating graph data inside the SVG component.

### Avoid premature custom-domain assumptions

The migration guide identifies all affected systems—site configuration, `CNAME`, Pages, DNS, HTTPS, canonical metadata, RSS, sitemap, assets, and base paths—but directs the owner to use GitHub's current DNS instructions after a real domain and provider are selected.
