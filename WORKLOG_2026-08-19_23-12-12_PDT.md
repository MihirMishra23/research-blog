## Design decisions

### Pin the project to the Node.js 22 release line

The repository declares `>=22.12.0 <23` and includes `.nvmrc` with `22`. This prevents accidental use of the machine's active, unsupported Node.js 23 runtime while keeping the documented baseline aligned with Astro's minimum requirement.

### Make static output explicit

Static output is Astro's default, but `output: 'static'` is stated explicitly in `astro.config.mjs` because GitHub Pages compatibility is a core project constraint.

### Use strict TypeScript from the beginning

The project extends `astro/tsconfigs/strict` so type assumptions are caught before content and interactive components accumulate.

### Include validation and formatting in the baseline

The baseline includes `check`, `format`, and `format:check` scripts in addition to Astro's development, build, and preview scripts. This gives later action items consistent verification commands.

### Use npm as the baseline package manager

The existing environment provided npm, and the official Astro generator defaults to it when invoked through npm. `package-lock.json` is now the lockfile and should remain the package-manager source of truth unless the project intentionally migrates later.

### Keep planning records outside automatic formatting

The spec, implementation checklist, and session worklogs are excluded from Prettier so automated source formatting does not rewrite historical planning records. Site content added later remains eligible for normal formatting.
