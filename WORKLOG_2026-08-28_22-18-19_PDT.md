## Design decisions

### Keep content lookup outside presentation components

Routes will query the `writing` and `topics` collections and resolve IDs into typed display data. Shared components accept labels, URLs, statuses, and descriptions as props. This keeps them independent of any particular article, topic, route, or sample content.

### Separate metadata resolution from navigation rendering

`resolveArticleNavigation()` translates `previous`, `next`, and `related` frontmatter IDs using the set of visible articles. `ArticleNavigation.astro` only renders the resolved result. Missing targets are omitted gracefully now; cross-entry validation remains owned by the later content/map validation steps.

### Use one article layout for Markdown, MDX, and route-rendered collection content

`ArticleLayout.astro` accepts a typed article metadata object plus optional breadcrumbs and navigation. It does not query content or assume a slug. The MDX rendering fixture now uses this same public contract.

### Keep maturity cues secondary to topic names

Maturity is represented with a small outlined or filled dot and text rather than a large badge or saturated panel. The text remains available to assistive technology and prevents color from being the only signal.

### Resolve base-path links at the final UI boundary

Shared components accept root-relative internal URLs or absolute external URLs. `siteHref()` applies the GitHub Pages base path only to internal links, keeping callers independent of the deployment location.
