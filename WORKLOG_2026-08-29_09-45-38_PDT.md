## Design decisions

### Keep the topic file as the single source of truth

The topic Markdown/MDX entry owns its name, summary, maturity, relationships, papers, conceptual orientation, and long-form explanation. The index and detail routes derive their UI directly from the collection.

### Separate concise orientation from long-form explanation

Five optional frontmatter fields populate a predictable problem-to-next-steps sequence. The document body remains available for equations, examples, caveats, and deeper prose, avoiding brittle attempts to extract meaning from Markdown headings.

### Make richer metadata optional

Framework steps and supporting sections render only when they contain data. A new topic can therefore start with the required core fields and a short body without producing blank cards or placeholder values.

### Derive articles in the reverse direction

Topic pages select published articles whose `topics` array contains the current topic ID. Authors connect an article once, in article frontmatter, and the corresponding topic page updates automatically.

### Preserve manually authored conceptual relationships

Prerequisite, before, next, and related groups remain distinct instead of being collapsed into one generic graph. This keeps the teaching intent visible and prepares the same canonical relationships for the map data model in action item 10.

### Group only populated categories

The topic index follows the canonical category ordering but omits empty categories. The index will expand automatically as new topic files introduce training, evaluation, agents, or other areas.
