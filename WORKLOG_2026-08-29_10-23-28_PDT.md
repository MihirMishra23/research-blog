## Design decisions

### Recreate the reference grammar instead of tracing the image

The map uses a central radial hierarchy, irregular hand-shaped ovals, handwritten labels, quiet notebook dots, organic connectors, and rare red annotations. The supplied screenshot is not included as a background and no pixel tracing is used.

### Keep the renderer deterministic and lightweight

Oval and connector paths are calculated from stable IDs and authored positions at build time. There is no graph library, force simulation, UI framework hydration, animated canvas, gradient, or large client dependency.

### Make every SVG node a real link first

Root, area, and topic nodes are server-rendered anchors. JavaScript progressively changes ordinary activation into selection, while modifier clicks retain normal new-tab behavior. If JavaScript is absent, every node still navigates somewhere useful.

### Limit selection to the immediate neighborhood

The map intentionally resolves one-edge adjacency rather than recursively highlighting whole branches. This keeps the visual response legible and matches the V1 requirement to explain local relationships.

### Use expansion semantics for the detail panel

Each SVG link declares the controlled panel and current expanded state. The panel uses an `aria-live` region for updates, while Return and Escape restore the overview and focus.

### Preserve map scale on mobile

Shrinking a 1536-unit drawing to 390 pixels would make labels and targets unusable. The mobile SVG therefore keeps a 62-rem minimum width, starts near the center, and pans horizontally inside its own scroll region. Minimum node hit regions render at approximately 46 CSS pixels.

### Keep the non-graph representation visible

The hierarchical topic list is not a hidden accessibility-only duplicate. It is an ordinary navigable section, remains available without JavaScript, and provides a compact alternative to spatial exploration.

### Defer final placement to the assembly step

The component is exercised on `/map-preview/` so Step 11 can be verified independently. Step 12 owns the final homepage narrative, exploration controls, recent writing, and focused `/map/` route.
