## Design decisions

### Keep the general site static

The production build emits no general-purpose JavaScript bundles. Small component scripts remain inline for the theme control, writing filters, code-copy controls, and map interaction. Pagefind's generated JavaScript is loaded only on `/search/`.

### Treat the mobile map as an intentional canvas

At 390px the document remains 390px wide, while the 992px map canvas scrolls inside its labeled container. The complete semantic topic list follows the visual map, so narrow screens and non-graph navigation do not depend on manipulating the canvas.

### Make production checks repeatable

`npm run verify:production` now audits the generated output rather than relying only on a visual spot check. It resolves URLs using the `/research-blog/` deployment base, validates fragments and generated assets, checks both theme palettes at the WCAG AA 4.5:1 text threshold, and guards against unnecessary JavaScript growth.

### Keep editorial content untouched

This quality pass changes tooling and documentation only. It does not generate or rewrite article-body prose.

## Known limitations intentionally deferred

- Search requires JavaScript. With JavaScript unavailable, the search page links to the complete Writing and Topics indexes.
- The visual map requires horizontal scrolling on a narrow viewport; its semantic text fallback remains fully available.
- Pagefind's supported Default UI is still in use. Migration to its newer Component UI is deferred until the extra accessibility and customization benefits justify replacing the current integration.
- Development fixture routes remain directly addressable, but they are excluded from search and the sitemap.
- Advanced graph features, personalized learning paths, analytics, and per-article social images remain in the post-V1 backlog.
