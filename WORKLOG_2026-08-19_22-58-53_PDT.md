## Design decisions

### Astro remains the default stack

The spec explicitly prefers Astro, and no repository constraints currently justify another static-site generator. The implementation plan therefore treats Astro with TypeScript and static output as the baseline.

### The first milestone is deployment-oriented

The plan orders work around getting a complete vertical slice live: project baseline, content, routes, simple map, discovery metadata, validation, documentation, and deployment. Advanced graph behavior stays deferred until the publishing workflow and core navigation are proven.

### The map will begin with SVG and static typed data

For six initial nodes, SVG plus a small interactive component is likely sufficient and keeps the JavaScript footprint understandable. Nodes, edges, and topic metadata will remain separate from the renderer so a more capable visualization approach can be adopted later if real requirements demand it.

### Content should have one source of truth

The content-modeling step must settle how a topic entry, topic page, and map node relate before sample content proliferates. The target developer experience is that adding a concept requires editing one concept record or topic content file, not synchronizing multiple unrelated files by hand.

### Accessibility is part of the map contract

Keyboard activation, touch behavior, assistive labels, and a semantic hierarchical fallback are acceptance criteria for map V1 rather than post-launch polish. Hover-only interaction is not considered complete.

### Worklog convention

Each substantial build session should create a new file named `WORKLOG_YYYY-MM-DD_HH-MM-SS_TZ.md`. Worklogs are append-only records for that session and should include:

- session objective;
- completed work;
- verification performed and its outcome;
- design decisions and rationale;
- deviations from the spec or action plan;
- open questions, risks, and the recommended next action.

The ordered backlog remains in `IMPLEMENTATION_ACTION_ITEMS.md`; worklogs should reference checklist items rather than becoming a second backlog.
