## Design decisions

### Treat this as a GitHub project site

The repository is named `research-blog`, not `MihirMishra23.github.io`, so the initial deployment requires the `/research-blog` base path. The deployment origin is `https://mihirmishra23.github.io` and the full expected URL is `https://mihirmishra23.github.io/research-blog/`.

### Keep content identity and deployment identity together

`src/config/site.ts` is the single source for site title, description, author placeholders, repository identity, deployment origin, base path, and future custom domain. `astro.config.mjs` consumes this module instead of repeating URL literals.

### Require base-aware internal URLs

Components should use `sitePath()` for root-relative page and public-asset URLs. This makes local development match GitHub Pages behavior and lets a future custom domain remove the repository prefix centrally.

### Use Astro's maintained deployment action

The workflow uses `withastro/action@v6` to install, build, and upload the site, followed by `actions/deploy-pages@v5`. Node.js 22 is explicit so CI matches the repository's declared engine rather than the action's newer default runtime.

### Do not set a placeholder custom domain

The custom-domain value remains `null`. Adding a fake `CNAME` would interfere with the initial GitHub Pages URL and create a misleading deployment configuration.
